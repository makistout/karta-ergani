# Mobile portal εντολών

Διαδρομή: `/mobile`. Σύνδεση με τον υπάρχοντα χρήστη γραφείου (`karta_user`),
με επιστροφή στο mobile μετά το login και τους ίδιους ελέγχους onboarding.
Απαιτούνται `work_card.view`, `stores.select` και, για υποβολή, `work_card.submit_live`.

## Προσωπικό και εμφάνιση

- Επιλογή από τα καταστήματα στα οποία έχει πρόσβαση ο χρήστης.
- Προσωπικό από το αποθηκευμένο σημερινό πρόγραμμα με ώρες εργασίας,
  ομαδοποιημένο ανά ειδικότητα της τρέχουσας σύμβασης (πόστο).
- Συμπαγή κουτάκια με ωράριο και πραγματικά χτυπήματα:
  `15:00 - 23:00 / Κάρτα: 11:24 - 12:40`. Ρολογάκι όπου λείπει χτύπημα.
- Τα χτυπήματα συνδυάζουν πραγματική απασχόληση και τοπικές δηλώσεις κάρτας
  με τους υπάρχοντες μηχανισμούς συγχώνευσης και νυχτερινής εργασίας.
- Ολοκληρωμένη ημέρα: όλα τα διαθέσιμα ζεύγη έχουν είσοδο/έξοδο και είναι
  τουλάχιστον όσα τα διακριτά ωράρια. Εμφάνιση σε κοινή ενότητα στο τέλος,
  αλφαβητικά, με ανενεργά κουτάκια χωρίς επιλογή.

## Εντολές

Πολλαπλή επιλογή, σταθερή κάτω μπάρα «Άνοιγμα» / «Κλείσιμο» και επιλογές
«Τώρα», «Πριν 5′», «Πριν 10′». Ο server υπολογίζει την ώρα Ελλάδας και
χρησιμοποιεί την υπάρχουσα διαδικασία `work_card_submit_office` / WRKCardSE.
Ελέγχει κατάστημα, ημέρα, επιτρεπτό offset και παρουσία στο σημερινό πρόγραμμα.
Δεν αλλάζουν οι κανόνες απολογιστικού ή υπολογισμού ωρομέτρησης.

Οι υποβολές εκτελούνται διαδοχικά, με ξεχωριστό αποτέλεσμα. Σε αποτυχία
σταματούν και δεν επαναλαμβάνονται αυτόματα. Τα επιτυχημένα αφαιρούνται
από την επιλογή και τα χτυπήματα ανανεώνονται από τη βάση.
Η ανανέωση της λίστας διαβάζει τα αποθηκευμένα δεδομένα· δεν αποτελεί νέο
συγχρονισμό από το portal ΕΡΓΑΝΗ.

## Αρχεία και έλεγχοι

`app/routes_mobile.py`, `app/templates/mobile.html`, `app/static/css/mobile.css`,
`app/static/js/mobile.js`, `tests/test_mobile_portal.py`.

```bash
python -m pytest tests/test_mobile_portal.py tests/test_work_card_aitiologia.py tests/test_access_control.py -q
node --check app/static/js/mobile.js
```

Εγκατάσταση με το κανονικό Flask/IIS deployment, χωρίς migration.
Μετά το pull χρειάζεται επανεκκίνηση/recycle του application pool και έλεγχος
`/mobile` → login → κατάστημα → προσωπικό. Μην υποβάλλετε πραγματικά χτυπήματα
για δοκιμή εμφάνισης. Τα assets έχουν version query για ανανέωση της cache.
