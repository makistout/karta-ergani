# Κανόνες & διαγράμματα — διαδικασία ενημέρωσης

## Πρόσβαση

Μενού **Απολογιστικό → Κανόνες & διαγράμματα**, `/ui/apologistic/rules`.
Απαιτεί σύνδεση γραφείου με κωδικό και ρητό ρόλο `super_admin`.
Admin, λογιστής, granular wildcard και office API token δεν παρακάμπτουν τον έλεγχο.
Η ίδια προστασία ισχύει σε κάθε HTML, Markdown, JSON, Word και ZIP, όχι μόνο στο μενού.
Τα αρχεία βρίσκονται στο `app/private/rule_diagrams`, εκτός `/static`, με `no-store`.

Η σελίδα περιλαμβάνει τα διαγράμματα με αναζήτηση/εκτύπωση, τη σειρά εκτέλεσης,
τον παλιό κατάλογο, την αναλυτική περιγραφή και τις καταγεγραμμένες αποκλίσεις.
Το Word εργατολογικού ελέγχου είναι **ιστορική έκδοση 14/08/2026, rules-v2**.
Δεν παρουσιάζεται ως επικαιροποιημένη ή εγκεκριμένη εργατολογική γνωμοδότηση.

## Υποχρεωτικά σε κάθε αλλαγή κανόνων

1. Αλλάζουμε τον κώδικα και τα σχετικά regression tests.
2. Συγκρίνουμε κάθε αλλαγμένο κλάδο με τα διαγράμματα στο
   `deliverables/rule_diagrams/build_diagrams.py`. Ενημερώνουμε συνθήκες,
   αποτελέσματα, σειρά προτεραιότητας, πηγές και αποκλίσεις. Προσθέτουμε κάθε νέο rule_id.
   Για νέο module κανόνων επεκτείνουμε το `SOURCE_FILES` στο `app/rule_diagram_versions.py`.
3. Ελέγχουμε ουσιαστικά τα διαγράμματα. **Το `--reviewed` δεν μεταφράζει αυτόματα
   νέο Python κώδικα σε σωστή φυσική γλώσσα**· δηλώνει ότι έγινε ο παραπάνω έλεγχος.
4. Παράγουμε νέα έκδοση:

   ```bash
   python -X utf8 scripts/build_rule_diagrams.py --reviewed
   python -X utf8 scripts/build_rule_diagrams.py --check
   python -m pytest -q tests/test_rule_diagrams.py tests/test_access_control.py tests/test_apologistic.py tests/test_apologistic_new_rules.py tests/test_timekeeping.py
   ```

5. Συμπεριλαμβάνουμε στο ίδιο commit κώδικα, διαγράμματα, το νέο immutable directory
   `app/private/rule_diagrams/rules-…`, το manifest και το CHANGELOG.
6. Κάνουμε push. Το GitHub workflow **Rule diagrams / validate** ελέγχει την
   αντιστοίχιση και τα tests. Αποτυχία σημαίνει ότι η αλλαγή δεν είναι έτοιμη για deploy.
   Το workflow από μόνο του δεν κλειδώνει direct pushes ή εξωτερικό IIS deploy·
   απαιτείται να επιλέγεται επιτυχημένο commit για εγκατάσταση.
7. Μετά την εγκατάσταση στο IIS: `python -X utf8 scripts/build_rule_diagrams.py --check`,
   recycle app pool σύμφωνα με την υπάρχουσα διαδικασία, και έλεγχος login/ρόλων.

## Έκδοση και ιστορικό

Το `rules-<hash>` προκύπτει από SHA-256 των αρχείων πηγής και δημιουργίας διαγραμμάτων.
Εμφανίζονται επίσης η έκδοση snapshot απολογιστικού, η έκδοση ωρομέτρησης και η
ημερομηνία ελέγχου. Το `source_commit` είναι το HEAD κατά την παραγωγή, ενώ τα
επιμέρους hashes προσδιορίζουν ακριβώς και τυχόν μη committed αλλαγές πηγών.
Τα ίδια δεδομένα δεν δημιουργούν νέα έκδοση. Διαφορετική πηγή δημιουργεί νέο φάκελο.
Οι παλιοί φάκελοι δεν αντικαθίστανται και επιλέγονται από το ιστορικό.

Το `--check` ελέγχει όλες τις αρχειοθετημένες εκδόσεις για αλλοίωση και την τρέχουσα
για αλλαγμένες πηγές/παραδοτέα. Αν ο εγκατεστημένος κώδικας δεν αντιστοιχεί στην τελευταία
έκδοση, εμφανίζεται προειδοποίηση στη σελίδα. Δεν τροποποιούνται υπολογισμοί ή δεδομένα.
